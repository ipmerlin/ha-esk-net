# ЕСК — личный кабинет для Home Assistant

Неофициальная интеграция личного кабинета **https://lk.esknet.net**, созданная на основе AppDaemon-скрипта `esk_net.py`. Работает непосредственно в Home Assistant, AppDaemon не нужен.

## Возможности

* Настройка логина и пароля через интерфейс HA, проверка входа перед добавлением.
* Баланс, дни до блокировки, тариф, стоимость тарифа в месяц и лицевой счёт.
* Несколько аккаунтов, отдельные cookie-сессии, защита от повторного добавления одного счёта.
* Обновление каждые 4 часа; в параметрах можно выбрать от 30 до 1440 минут.
* Повторный ввод учётных данных при отказе авторизации.
* При недоступности сайта сущности становятся недоступны; отсутствующие дополнительные поля получают `unknown`, а не выдуманный ноль.
* Русский и английский интерфейс; диагностический файл без учётных данных и финансовых значений.

Минимальная целевая версия: **Home Assistant 2025.12**. Интеграция читает HTML, поскольку в исходном скрипте нет документированного API. Изменения сайта могут потребовать обновления парсера. Операции оплаты, смены тарифа и обещанного платежа не реализованы.

## Установка через HACS

Репозиторий: [ipmerlin/ha-esk-net](https://github.com/ipmerlin/ha-esk-net).

1. В HACS откройте меню → **Пользовательские репозитории**.
2. Добавьте `https://github.com/ipmerlin/ha-esk-net`, тип **Интеграция**.
3. Найдите **ЕСК — личный кабинет** и скачайте.
4. Перезапустите Home Assistant.
5. **Настройки → Устройства и службы → Добавить интеграцию → ЕСК**.
6. Введите логин и пароль личного кабинета.

Автоматическое появление в общем каталоге HACS — отдельная процедура. Для установки из пользовательского репозитория она не требуется.

## Ручная установка для первого испытания

Скопируйте каталог `custom_components/esk_net` в `/config/custom_components/esk_net` на сервере HA, перезапустите HA и добавьте интеграцию через интерфейс. Если используете подготовленный архив `esk_net-0.1.0.zip`, распакуйте его в `/config`: внутри уже есть `custom_components/esk_net`.

## Переход с AppDaemon

Сначала отключите приложение `EskNetParser` в AppDaemon. После установки проверьте сущности нового устройства ЕСК. Их идентификаторы HA формирует автоматически; старые `sensor.esk_net_balance`, `sensor.esk_net_days_left`, `sensor.esk_net_tariff`, `sensor.esk_net_account` автоматически не переносятся.

Обновите ссылки в карточках и автоматизациях либо назначьте новым сущностям прежние идентификаторы через настройки, когда старые освободятся. Новый датчик тарифа содержит только название; цена вынесена в отдельный датчик и атрибут `monthly_price`. Единица баланса — `RUB` (отображение зависит от HA). Перед удалением старого приложения сравните показания с ЛК.

## Обновление и диагностика

Параметры интеграции меняют интервал опроса. Для внеочередного чтения вызовите действие `homeassistant.update_entity` для любого её датчика — координатор обновит все показания одним запросом данных.

`cannot_connect` означает сетевую ошибку/HTTP-ошибку, `invalid_auth` — отказ авторизации или возврат формы входа, `cannot_parse` — неожиданный HTML либо незавершённую проверку сайта. Изменение вёрстки не трактуется автоматически как неверный пароль.

Пароль хранится стандартным механизмом config entries HA. Не размещайте `.storage`, пароли, cookie или выгруженные страницы ЛК в GitHub. Диагностику можно скачать из меню интеграции; исходный HTML интеграция не сохраняет и не журналирует.

## Проверки и границы готовности

Локальные тесты используют **синтетический HTML**, собранный по селекторам исходного скрипта, и подставные HTTP-ответы. Они не подтверждают вход в реальный ЛК. Полный запуск HA на этой Windows-машине не выполнялся. Перед стабильным релизом нужно проверить добавление, смену пароля, перезапуск, выгрузку и показания в настоящем HA.

```shell
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -p "test_*.py" -v
python -m ruff check .
python -m ruff format --check .
```

GitHub Actions запускает эти проверки, hassfest и отдельные тесты настройки, повторной авторизации, координатора и выгрузки на Home Assistant 2025.12. Проверка HACS запускается вручную; для общего каталога потребуется также оформить бренд в `home-assistant/brands`.

## Публикация

1. Используйте публичный GitHub-репозиторий `ipmerlin/ha-esk-net` с описанием и topics `home-assistant`, `hacs`, `esk-net`.
2. Загружайте изменения проекта без `.venv`, `dist`, секретов и HTML своего кабинета.
3. Дождитесь успешных GitHub Actions и запустите ручную проверку HACS.
4. Испытайте интеграцию в HA; затем создайте release `v0.1.0`.

Если название репозитория другое, измените `documentation` и `issue_tracker` в `manifest.json` и ссылки в README.

Архитектура: [Config flow](https://developers.home-assistant.io/docs/core/integration/config_flow/), [DataUpdateCoordinator](https://developers.home-assistant.io/docs/integration_fetching_data/). Требования публикации: [HACS](https://www.hacs.dev/docs/publish/integration/).
